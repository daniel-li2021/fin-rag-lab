# Release validation plan

Status: **active preparation; release blocked on independent review and holdout custody**. Purpose: evaluate the implemented local prototype without treating development checks as authentic release accuracy. Current baseline and completed work are in [STATE](../STATE.md); this plan owns only remaining work.

## Sequence

1. **Review existing evidence first.** Independently review the retained [full historical control](../benchmarks/20261003-product-regression/capture/) for strict outcome/rubric correctness, numeric identity, issued-citation support and false refusals. Second-review release-critical development bindings/calculations and genuine revision mappings against originals under the [metric policy](../PRODUCT_METRIC_POLICY.md). Record reviewer identities, coverage and unresolved exceptions. Codex development review is not independent judging.
2. **Seal the release set.** An independent custodian must curate 48 authentic holdout cases: eight per primary slice, at least 20 numeric/calculated, with disjoint report families, company-period keys and revision lineages. The 2021 reserve is a proposal, not an acquired or sealed corpus. Audit annual comparatives, amendments, graphs and repeated tables for leakage; replace overlapping families. Never invent revision diversity to fill a denominator. Freeze expected outcomes, gaps, exact original locators, definitions, periods, operands, tolerances and narrative rubrics before viewing answers. Keep sealed labels outside development access; commit hashes/split rules.
3. **Freeze a matched evaluation.** Declare corpus/build identities, model/configuration, cache mode, original-evidence budget, review policy and bounded paid allowance. Existing October 3 control differs from earlier model/vector configurations; it cannot prove the matched historical cost/non-regression gates. Reuse it wherever valid; capture a new matched baseline/arm only when required and authorized. Preserve every prior capture.
4. **Repair measured failures.** Work from the reviewed ledger, changing one variable per experiment. Prior failure mappings in the [evaluation contract](../PHASE_3_EVALUATION.md#defect-to-contract-map) cover sparse table binding, period confusion, incomplete risk/ranking coverage and supported-but-refused answers. Review exact numeric and narrative claim support, not quote location alone. Do not enlarge context or add a planner to compensate for missing facts.
5. **Publish the decision.** Report per-case paired wins/losses, false refusals, slice/cross-tags, required evidence and operand coverage, priced/unknown receipts, stage/end-to-end p50/p95 and reviewer scope. Retain withheld/failed outcomes. Reuse the actual [local screenshots](../screenshots/product-local-20261003/); add authentic source-update/rerun evidence where missing. An induced refresh failure is an operational test, not an authentic financial revision. Mark release passed only after every applicable frozen gate passes.

## Acceptance authority

The [Phase 3 evaluation contract](../PHASE_3_EVALUATION.md#frozen-gates) owns the unchanged release thresholds: historical strict/numeric/clarification/OOC/cross-document gates, holdout overall and per-slice strict results, numeric accuracy, complete evidence, cited operand coverage, zero safety failures and matched cost/latency bounds. [BENCHMARK](../BENCHMARK.md#promotion-gate) separately owns retrieval promotion. Unknown review/usage denominators cannot pass a gate.

The product proposal also specified at least eight narrative and eight answerable cross-company cases per split, with **7/8 strict** in each subgroup, and at least 12 holdout answerable cases needing two distinct report families. Preserve these additional requirements when sealing; the development labels already include eight of each subgroup. Do not count repeated values in companion decks as independent multi-document evidence.

Existing contextual promotion requires two more factual numeric successes, which is impossible against a 9/10 baseline on ten questions. Keep that experiment held; a new retrieval gate requires an explicitly approved larger paired design, not a retroactive relaxation.

## Deferred boundaries

- Planner: disabled until deterministic research passes authentic gates and at least five supported development failures are specifically decomposition/routing failures while explicit tasks succeed. Then freeze a fresh planner comparison; the [existing planner gates](../PHASE_3_EVALUATION.md#frozen-gates) still apply.
- Public demo: separate release requiring server-enforced read-only access, TLS/access control, isolated data, server-only secrets, session-separated research, no public uploads/fetch/review/admin routes and hard request/model allowances. Current owner navigation/token is not multi-user authorization. Measure the expanded Streamlit/API/database process set before choosing hosting capacity. Dated [private estimates](../PRIVATE_DEPLOYMENT.md) are not a public capacity guarantee.
- Frontend rewrite, more companies, broad XBRL, automatic semantic promotion, arbitrary formulas/FX/TTM/YTD/Q4 derivations, ANN/search services and scheduled refresh: reconsider only for a measured requirement. Any new plan must be registered in [INDEX](../INDEX.md).

## Closeout

After each implemented step, update the affected contracts/KB, evidence report, STATE and this plan in the same change using [CONTRIBUTING](../../CONTRIBUTING.md). When complete, move durable outcomes to STATE/decisions/results and remove this plan from INDEX; delete it unless its exact original is needed to reproduce an experiment.
