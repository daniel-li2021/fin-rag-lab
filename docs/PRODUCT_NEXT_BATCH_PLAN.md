## 2. Biggest remaining gaps

1. **Authentic usability:** original-location/value checks do not establish metric, period, row/column, scope or basis semantics. New source versions/builds need new bindings. There is no populated reviewed history or sealed release benchmark.
2. **Comparability:** matching `metric_id`/scope/basis strings is necessary but cannot certify economically equivalent definitions. Add a small documented metric/definition policy, particularly bank revenue, parent-attributable versus consolidated net income, segment membership, automotive versus consolidated margin, and operating counts versus accounting basis. Exact AMD fiscal intervals differ from Tesla/Wells Fargo calendar intervals.
3. **Narrative value:** lexical candidates do not answer “what changed and why?” A bounded synthesis step needs source-balanced coverage and claim support, with management explanation distinguished from established causality. A planner cannot repair this absence.
4. **Scaling limits:** the service loads all cards for selected builds and rejects above **100**, even for a tiny task. Requests allow **18 sources, six tasks, three companies and three periods**; templates express only one period or a two-period trend. Ask's compatibility retriever caps selected children at **10,000**; evidence search rebuilds BM25 per task. Larger corpus size does not imply unrestricted collection-wide querying. Filter cards by required dimensions before the bound; use narrow selections and measure before caching or changing retrieval.
5. **Product visibility:** Research exposes raw metric names, a rigid question grammar and JSON receipts/citations. Margin and delivery/production operations exist in the API but are not exposed by its guided form; segment scope also needs explicit tasks. The usual README setup opens the legacy Ask path, so research/history can be missed entirely.

Later extraction evolution: **original table/text candidate → deterministic locator/value/unit/date/definition checks → approved mapping or review queue → immutable eligible observation**. Use explicit issuer/form/table mappings first; an optional model proposes candidates only. Header ambiguity, revised scopes, unresolved dates and conflicts require human review. Today's `reviewed` status still requires manual semantic attestation; automated promotion would need an explicit new policy, extraction precision/recall evidence and audit sampling. Track minutes per reviewed fact, exception rate, invalid bindings and rebuild churn before automating. Keep candidates separate from answer-authorizing facts and reuse approved cards only for their pinned evidence.

## 8. Criteria for starting Agent work

The existing graph, typed requests, pinned manifests, task/repair/context bounds and calculation validators provide an execution boundary. They do **not** establish planner readiness: real bindings, narrative coverage, trusted task validation and sealed results remain prerequisites.

Use **simple question → direct path; known comparison → deterministic evidence plan; complex supported research → optional bounded planner → validated tasks → existing engine**. Clarify missing user dimensions before planning. Never ask a planner to manufacture source facts, metric equivalence, dates, formulas or permissions.

Start an experiment only after the deterministic product passes its authentic gates and a reviewed development failure ledger identifies at least **five supported questions** that fail specifically because of decomposition/routing, while explicit tasks already succeed on the same evidence. Missing facts, poor retrieval, manual-review backlog and attractive agent branding are insufficient reasons.

Freeze a fresh planner comparison/holdout before looking at outputs; the earlier product holdout is spent once used for tuning. One structured planner call, at most six validated tasks/three companies/three periods, two retrieval attempts per task and 6,000 original tokens; zero planner calls for simple/known paths. Validate source authorization, supported metric definitions, periods, operations and coverage before execution; malformed/unsupported plans clarify or fail safely. Treat retrieved instructions as untrusted document content.

Ship only with the existing predeclared **≥3 additional strict holdout successes**, no previously correct loss, all safety gates intact, and complex mean cost/p95 ≤1.5× matched deterministic execution. Report invalid-plan rate and required-task recall as well as final answers. Measure incremental planner cost, not just cached total cost. If gains do not pass, retain the deterministic product and keep the planner disabled.
